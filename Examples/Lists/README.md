# Copy lists between Juriba DPC instances

These scripts copy dynamic list definitions from one Juriba DPC instance to another, for example from a test instance to production.

- `Export Lists.ps1` saves the lists you choose to a JSON file.
- `Import Lists.ps1` creates them on another instance and writes a CSV report.

## Why lists can't just be copied

A list is saved as a query that refers to fields and values by IDs, for example `customField_5_1101`, `project_130_ringId EQUALS ('235')` or `DepartmentKey EQUALS ('14')`. These IDs are generated by each instance, so the same custom field, project, ring or department has a different ID on another instance, or may not exist there at all.

The export records the name of everything a list uses. The import looks each name up on the target instance and rewrites the query with the target's IDs. This covers:

- custom fields, including owner custom fields
- projects: project properties, stages, readiness, tasks, task values, slots, task owners and teams
- rings, buckets, paths, capacity units, Evergreen capacity units and self service fields
- departments (matched by their full path, e.g. `Sales \ Account Management`)
- imports, LDAP and import properties, automation fields
- other lists used in "Saved List" filters

Built-in fields such as `hostname` are the same everywhere and are kept as they are.

## What is not copied

- Static lists and association lists.
- List sharing. Imported lists are owned by the user of the API key and are not shared. Set sharing afterwards in DPC or with `Set-JuribaListAccessType`.
- List descriptions, tags and favourites.

## Requirements

- PowerShell 7
- The `Juriba.DPC` module, version 1.1.25.0 or later: `Install-Module Juriba.DPC`
- An API key for each instance. The import key's user will own the new lists.

## Usage

### 1. Export

```powershell
# Named lists
.\"Export Lists.ps1" -Instance "https://source.dpc.juriba.app" -APIKey "xxxxx" -ObjectType Device -ListName "Windows 11 Ready", "Windows 11 Blocked"

# By id
.\"Export Lists.ps1" -Instance "https://source.dpc.juriba.app" -APIKey "xxxxx" -ObjectType Device -ListId 101, 102

# Every dynamic list
.\"Export Lists.ps1" -Instance "https://source.dpc.juriba.app" -APIKey "xxxxx" -All
```

| Parameter | Description | Default |
|-----------|-------------|---------|
| Instance | The DPC instance to export from | |
| APIKey | An API key for that instance | |
| ListName / ListId / All | Which lists to export | |
| ObjectType | Device, User, Application and/or Mailbox | All four |
| ExcludeDependencies | Don't add lists that are only used by "Saved List" filters | Off |
| OutputPath | Where to save the export | `.\lists.json` |

If a list uses another list in a "Saved List" filter, that list is exported too and imported first.

### 2. Dry run

```powershell
.\"Import Lists.ps1" -Instance "https://target.dpc.juriba.app" -APIKey "xxxxx" -InputPath .\lists.json -DryRun
```

This checks every list against the target and writes the report without creating anything.

### 3. Import

```powershell
.\"Import Lists.ps1" -Instance "https://target.dpc.juriba.app" -APIKey "xxxxx" -InputPath .\lists.json
```

| Parameter | Description | Default |
|-----------|-------------|---------|
| Instance | The DPC instance to import into | |
| APIKey | An API key for that instance | |
| InputPath | The export file | `.\lists.json` |
| ReportPath | Where to write the CSV report | `.\list-import-report.csv` |
| NameSuffix | Text added to every list name, e.g. `" (imported)"` | None |
| Overwrite | Replace lists you already own with the same name and list type. Lists owned by other users are never changed | Off |
| DryRun | Report only, create nothing | Off |

## Reading the report

| Status | Meaning |
|--------|---------|
| Created | The list was created. |
| CreatedBroken | The list was created but DPC reports it as broken. Open it in DPC to check its filters. |
| Updated | The list already existed and its definition was replaced (`-Overwrite`). |
| UpdatedBroken | The list's definition was replaced but DPC reports it as broken. |
| Exists | You already own a list with the same name, so it was left alone. |
| Skipped | Something the list uses doesn't exist on the target (see MissingReferences), a list it depends on wasn't imported, the name with `NameSuffix` is longer than DPC's 50-character limit, another list in the export has the same name, or the existing list can't be overwritten because it's a different list type. See Reason. |
| Failed | The API call failed. See Reason. |
| WhatIf | Dry run: the list would be created or updated. |

MissingReferences names what couldn't be found, for example:

- `Column 'Custom Fields > Cost Centre'`: create the custom field on the target, then import again.
- `Filter 'Project-Win11 > Properties > Win11: Ring'`: the project doesn't exist on the target, or has a different short name.
- `Value 'Ring 2: Pilot' of filter 'Project-Win11 > Properties > Win11: Ring'`: the project exists but has no ring with that name.

Names must match exactly, including project short names, because they are what identifies a field or value across instances. Fix the missing items on the target (or rename them to match) and run the import again. Lists that were already created are reported as Exists and are not duplicated.

## Using the module functions directly

The scripts are thin wrappers around these module functions:

- `Export-JuribaListDefinition` and `Import-JuribaListDefinition` do the export and import.
- `Get-JuribaListField` and `Get-JuribaListFilter` list the columns and filters available for an object type, with the token used in list queries and the signature used to match them across instances.
- `Get-JuribaListFilterOption` lists the values a filter accepts.

Run `Get-Help <function> -Full` for details.
